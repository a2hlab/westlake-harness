# HanBing HelloWorld Bring-up Staircase

- Long-term goal: unmodified Unity Android games render a stable first frame on OpenHarmony.
- Short-term goal: canonical HelloWorld starts through production appspawn-x and remains alive without a crash.
- Canonical adapter: `/opt/Bridge/src/adapter`
- Product-input rule: source, scripts, resources, APKs, and build artifacts come only from the canonical adapter; external installed compiler/toolchain executables are allowed only with path/version/SHA provenance.
- Evidence rule: `build_pass` and `device_verified` are independent gates; host success never implies device success.

## Current problem

There is no remaining compilation, init ownership, Activity, WMS-session, or
first-frame wall for the frozen r18 HelloWorld generation. The production
AppSpawnX route reproduced on D600 5eab after reboot, and first-frame plus
basic click evidence is closed in
`out/helloworld-r18-v7-ams-parent-bound-subwindow-repro2-5eab-20260725T082651HKT`.
The remaining strict gates are narrower than the requested on-screen
reproduction: H05 still requires an explicit `APPSPAWNX_NO_JIT=1` receipt, H06
still requires its frozen Application marker, and H08 requires the full
five-minute observation window.

## Design consistency

- No ART/class_linker/vtable modification is permitted.
- No BCP Java semantic modification is permitted.
- No build result is promoted past `build_pass` without assigned-device truly-cold evidence.
- No Java business-semantic change may be used to avoid a runtime wall.
