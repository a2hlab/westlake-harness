## B. 方法论陷阱（别再犯）

1. **别数子串**：`grep -c NewDetailActivity` 会命中服务端 settings JSON。活动是否启动只看行首生命周期行(onCreate/onResume/START/Displayed/`[B47-SLA] ENTRY`) + 截图。
2. **别数 dmesg 行数**：环形缓冲已满，前后行数不变会漏掉新 avc；直接 grep 原文。SELinux normal_hap 是 Enforcing，su 域是 permissive。
3. **缺栈别硬归因**：SIG11/SIGABRT 没抓到 native 栈时，不宣称是 metasec/Bionic/JIT。DFX 有配额(单 UID 60次/24h)、只处理首个信号 → 常常无 cppcrash。要栈就上被动记录器(out-crash42/recorder)。
4. **一次只改一个变量**：别把两个修复(如空壳+JIT#50)同时上再测，崩溃因果会不可分。
5. **观察窗 ≥40s**：真实详情页启动可能在触摸后 15-26s 才发生，短窗会漏。带视频文章要 ≥120s 才见 metasec/OOM 层。
6. **区分同意点击 vs 条目点击**：run 里有两次 uinput，queueMs 引用前先分清是哪次。
7. **截图是地面真相**：日志信号模糊时以 after-Ns 截图为准（正文页 vs 信息流 vs 宿主）。外环判早过多次都是只信日志。
8. **maps 取全**：`hdc recv /proc/PID/maps` 只得约 4KB 截断；要板上 cat 到文件再 recv。
9. **VT 空树 + P4b pass = 取证缺口，不是画面缺失**：child.stderr 的 `VT ==== root[0] ==== … VT ==== end ====` 之间零 rect 行、但同 log 有 mAppVisible<-true/DecorView 标记且 P4b(RenderService 见窗)过 → 窗口在、渲染链通，是 tap/VT 通道本轮无输出（#22/#40/#47 burgerking 同型）。判据侧应把该组合告警为“取证失败”而非记 P4a fail。重跑大概率过。
10. **split APK 的 dex 搜索会落到语言 config split**：candy/discord 的 launcher 类在 base APK（classes3.dex/classes.dex，strings 可证），装载器却在 ~64KB 的 config.en/ar split 里反复 `Unable to find entry`（EOCD 偏移≈split 尺寸即铁证）→ 活动停在 inflate 前。splits 明明 staged（ASX_SPLIT_APK_PATHS）——是 base/split 的 dex 搜索顺序缺口，非 splits 缺失、非 AAsset 回归。

11. **dlopen 是 depth-1 符号作用域**：OH musl 里被 dlopen 的库，其未定义符号只在自己**直接 DT_NEEDED**+全局作用域解析，不看传递依赖——metasec 缺 `__system_property_read` 不能靠 depth-2 的 libbase 兜，必须补到它直接 NEED 的 libandroid。补缺符号要**一次算全闭包**（UND−直接依赖导出，脚本 metasec_direct_missing.py），别一轮补一个：板子每次只报字典序第一个缺符。
12. **桩/no-op 别拍脑袋返值**：分发口返 `Object` 时，返 null 会被 Java 自动拆箱→NPE，返错类型→CCE。必须先逆 cmd→返回类型表（dispatch_map.py）再按类型返非空；Boolean 的 true/false 要读调用点控制流（自旋等待循环 `while(!a())sleep` → 必 true），聚合表看不出来。
13. **拒库判据:"挂 malloc" vs "调 malloc"别用 `strings|grep`(#48)**：`strings|grep malloc` 同时命中 (a).dynsym 的 **UND 导入**(库**调用** malloc,无害)和 (b).rodata **字符串常量**(库把 `"malloc"` 当 hook 目标传给 shadowhook/bytehook,才损坏 mallocng)。只 (b) 该拒。正确判据:`readelf -p .rodata` 取 malloc-family hook 目标串 **+** hook-install 导入(`*_hook_all/single/partial/sym_name/sym_addr`),不是 UND 导入。粗判会误伤功能库:#48 broad 拒 17 库时把 libhotfix-opt(挂非 alloc)也拒了→类初始化失败 app _exit(1) ~61s。收窄后拒 7=#49 两个+memsponge/monitorcollector/jato/sysoptimizer/npth_vm_monitor;保留 hotfix/turbo/tunnel/… 与 libnpth。拒后必须断言无新 exit(1)。**⚠️更正(B.14)**:本条曾据"libnpth 挂 malloc 但 fresh 存活不崩"保留 libnpth——错了,libnpth 就是真凶(见 A.9)。
14. **fresh 存活≠某库安全:先确认它在 fresh 真加载了(#48)**：warm 崩、fresh 活时别急着说"fresh 有的库都安全"。头条整个字节监控群(npth/bytehook/shadowhook/monitorcollector/godzilla/jato…)是**同意门控**——fresh 同意前 maps **加载 0 个**,warm 保留同意才全量加载。所以"fresh 3/3 存活"只证明"这些库没加载",**不证明任何一个安全**。我据此错留 libnpth 多轮。天然对照只在"两组唯一差异=被测变量"时成立;这里差异是整群,不是单库。用排除法(逐个拒到只剩一个仍崩)+ 崩溃 maps 的 loaded 集交集定位真凶。另:**LD_PRELOAD 拦截在 OH musl 有命名空间盲区**——拦 libc 符号(dlopen)全局有效,但拦别的库导出符号(bytehook/shadowhook)只在 shim 所在命名空间生效,monitor 在别的命名空间调就绕过;dlopen-refuse 能拒(libc 级),API 拦截不一定行。

15. **板上 toybox `grep -a -c` 对大 stripped 二进制假阴性(#48,claude-2,2026-09-27)**:21MB stripped libart 上 `grep -a -c` 连控制串(JNI_OnLoad)都返 0 → 误判"记录器不在 libart",白绕一大圈找部署单元。**搜 .so 字面量务必 `hdc file recv` 到 Mac 用真 grep**,别信板上 toybox grep 大二进制的计数。
16. **NATIVE_PRELOAD 里导出 libc 符号(sigaction)会破坏 OH 运行时 dlopen 加载(#48,claude-3,2026-09-27)**:零 DT_NEEDED 的 preload .so 若**导出/interpose `sigaction`**(或 malloc 族之外的 libc 符号)→ OH 运行时 dlopen 它静默加载失败(observer 不武装、app 缺 shim ~2s pc=0x0 崩)。**malloc 族导出没事**(v2/v3 都导出且正常加载)。修:sigaction 当纯 UND 直接调、别导出。**BIND_NOW 不是原因**(v3 也 BIND_NOW+零 DT_NEEDED 却加载),UND 闭包也 clean——唯一结构差异就是导出的 sigaction。自测必须走 `dlopen(RTLD_NOW|RTLD_GLOBAL)`(=板实际 NATIVE_PRELOAD 加载路径),LD_PRELOAD 单测抓不到 dlopen 加载失败。
17. **OH6.1 交付 libart 部署=plain `$RT/libart.so` 覆盖,不是内容寻址(#48,claude-2,2026-09-27)**:crash-census 文档的 `/system/lib64/westlake/route-a/<sha>/libsigchain.so` 内容寻址是 **OH7.0**(oh-7.0.0.38-board-libraries.txt),本板 OH6.1 不适用。活 libart = `$RT/libart.so`(=`/data/local/tmp/asx/libart.so` bind-mount,inode 321048,root 可写),plain overwrite + sha 核 + 备份。别去找 route-a 目录(不存在)。libart swap 高风险(ART 核心)→部署后先确认 app 起来渲染 feed,起不来立刻从 .bak 回滚。
18. **测性能前先清残留子进程(2026-09-25)**:`probe_source_app.py` 退出时不杀 child,每次重拉都留下上一个头条(各 500–680 MB RES)。六轮就把 7.5 GB 内存+swap 吃满 → kswapd 抖动 → UI 延迟数秒,极易误判成 Westlake 慢。量延迟前 `for p in $(pidof com.ss.android.article.news); do [ $p != <keep> ] && kill -9 $p; done` 并看 `free -m`。`kill -3` 对 child 安全(ART Signal Catcher),会把全部 Java 栈打到 child stderr。

## D补:横向 LocalSend/Flutter pc=0 = Impeller GLES 扩展 proc 缺失(claude-3,2026-09-27)
- **现象**:Flutter app 首帧 "1.raster" 线程 pc=0(blr NULL)。libflutter.so .bss@0xaee000 是全局 GLES ProcTable;主填表器(adrp 0xaee000;str [x8,#N])填核心 proc #960–#3512(跑了),但扩展区(#3520+,含崩溃槽 #468=偏移#3744)由独立 eglGetProcAddress+cbz-null-skip 加载器填。
- **根因**:此版 libflutter **Impeller 默认**(串 `[Action Required]: Impeller opt-out deprecated`)。某扩展 GL proc 在 OH GLES 驱动 getProcAddress 返 NULL(驱动宣称扩展但不导出其函数),null-guard 跳过存储→槽 0,Impeller 光栅路径**无条件 blr**(不像 Skia 先 null-check)→pc=0。
- **修法(通用于 OH 上任何 Flutter app 的 GLES proc 缺口)**:①关 Impeller→Skia GL(防御性,容缺失扩展 proc):manifest `io.flutter.embedding.android.EnableImpeller=false` 或 shell arg `--no-enable-impeller`;②`--enable-software-rendering`(绕开 GL 表,保底);③LD_PRELOAD 拦 eglGetProcAddress 记 NULL 名→GLES-shim。判据:表基 adrp、崩溃偏移 vs 主填表器终点(超出=扩展区)、libflutter 后端串。**⚠️更正(2026-09-27 实测,见 `benchmark/2026-09-27-framework-x-localsend-smali/README.md` L30–40)**:①② 在 LocalSend 这版 libflutter 上**都无效**——EnableImpeller=false 两条注入路径(ApplicationMetaDataReader + direct-launch AppSchedulerBridge)都确认执行了,崩溃地址一字不差(libflutter+0x4b6560),因为此版已废弃 Impeller opt-out;release 版 FlutterActivity 只在 debuggable 时读 intent shell-arg,所以 `--enable-software-rendering`/`--no-enable-impeller` 也进不去。只剩 ③:eglGetProcAddress 记录器点名槽 #468 的 NULL 扩展 proc 再补/桩它,或给 libflutter 打二进制补丁。
- 证据 westlake-harness `benchmark/2026-09-27-localsend-bringup/`(claude-2)+ merged48 `benchmark/2026-09-27-localsend-impeller-re/`(claude-3,harness 15fd424)。
