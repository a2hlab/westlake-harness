## Process selftest gate and promotion criteria

`process_selftest.py` inventories **every record**, complete hilog, target BMS UID/PID and each process's exact `[WL-KS-PROBE] selftest error` lines and `validateAead(...)=OK` lines. It recognizes the actual success form `validateAead(random 256-bit SecretKeySpec)=OK`. Failures are counted separately as `selftest_error`, `badtag` (both selftest and validateAead AEADBadTagException forms), and `probe_error`. The U10.1T8 Toutiao line is a known old **badtag defect**, not a zero-error unknown. Success accepts both `selftest validateAead(random 256-bit SecretKeySpec)=OK` and `validateAead round-trip=OK` (also direct validateAead=OK). Unseen PID, missing/incomplete log or absent success is unknown, not zero-error success.

Default gate: every process that reaches the probe must PASS with explicit validation OK and no failure of any of the three classes. Any selftest_error/badtag/probe_error unconditionally vetoes promotion, even if success also appears or an outer explanation is supplied. Only unknown probe coverage may be individually explained by outer, each exact record/PID, exact report/package binding and an existing evidence file with its hash. Multiple silent PIDs cannot be hidden behind a record-wide explanation. No exception is approved or written by this draft. A counter-only or blanket explanation is rejected. Crypto report SHA and the measured-record set must be bound by the outer Stage A decision.

`promotion_hook_u13.py` derives the U12 `retention_reason` safeguards: activation smoke, exact final bundle/manifest and outer signer, all signed-reference-lit keys measured and same_or_lit under k/n, zero confirmed regression. It changes the visual reference field to `u13_reference_lit_total`122 and adds the crypto report gate. This file is a criteria blueprint only; it has no apply/finish/device code. Final promotion must also retain the U12 production hook's identity/fingerprint gates, fresh same-board/window HW/ZZ outer signature and unconditional restoration on failure. There is no Toutiao bright-screen promotion condition.

Production observation wiring is now explicit: `after_shard_record_only` invokes `observe.py shard` immediately after each batch return, before sealing and before the next shard. It runs `process_selftest.report`, writes `selftest/<shard>.json` outside the sealed capture tree, and ACKs every error event and unknown. An assessment exception or missing records is unknown. Stage A only observes: neither a selftest REJECT nor unknown stops the remaining shard or overrides finish. The generic runner also records observer exit/exception; such a failure cannot be mistaken for passing promotion. Standard shard transport/cleanup failure still stops, with unconditional finish.

Admission remains ONLY in `promotion_hook_u13.py`: all three failure classes hard-reject; exact outer explanations apply only to unknowns.
