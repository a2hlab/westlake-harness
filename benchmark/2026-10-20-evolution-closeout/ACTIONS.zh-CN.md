| 优先级 | 问题与后果 | 这次已做 | 仍要优化 |

| 时点 | 工具或产物 | 状态和边界 |
| --- | --- | --- |

| 构建时 | 原编译器与原包重放、输入哈希、原始 stdout/stderr/rc、private-index 根重放 | 已有并在本轮复用；增量重链不等于所有对象可从零重编 |
| 开窗前 | `host_hap_preflight.py`、本板 fresh intake、原包回退、签认模板和 peer | 新工具已落地主线；目前只验精确 T33 输入，不能泛称三板通用，也不能把旧 intake 当 fresh 授权 |
| 派单后至采认 | 现有 ACK 与负状态哨、产物/提交核对、外环采认回执 | 本轮已用；统一队列与失联自动告警仍是下一项工具工作 |
| 收窗后 | harvest → retro → 外环判断 → FLAW/DIGEST/RUNBOOK → 可执行门禁 | 本轮留回执；指标仅诊断，不让自动候选数量替代跨事件判断 |

下一轮工具验收应覆盖：旧 ACK 不唤醒、新 blocked 必唤醒、完成未采认能报警、观察进程退出能被发现；采集器处理旧板全文与新增尾部结果一致、截断/轮转不丢卡、重跑不重复卡。这里只列明确的后续工作，不宣称已经实现。

## 哪些 API / 方法可以 freeze

这里把用户的 “free” 按项目惯例理解为 freeze（冻结）。

| 对象 | 目前证据 | 本轮处理 |
| --- | --- | --- |
| `AudioTrack.native_get_buffer_size_frames()I` | T18 精确源码与生产配方、头条实窗；后继 5cd 视频验收 | 待第二个不同 APK 证明该墙消失，并拆清冻结源范围；不新增冻结 |
| ANW/YV12 与无资源 `RequestBuffer` 失败恢复 | T30 两个编译单元、T31 5cd 实际留板；首次 NO_BUFFER 根因仍未知 | 待第二个不同 APK、窄错误分支和原行为回归证据；不泛化全部错误重试 |
| 去宿主开发页的 HAP 配方 | T32/5cd、T33/61b 同签覆盖与真实图标到 feed | 固定源/编译器/签名配置/9 成员差异的可复用方法；不是新增 Android 公共 API |
| 原包编译重放、离线预检、原件索引核验 | 精确输入、真实正例、负例和消费入口测试 | 入库复用，保留作用域与拒绝条件；不自动提升为任意产物通用规则 |

公共 API 冻结仍要求至少两个不同 APK，其中至少一个 t20 亮屏，其余证明该 API 失败消失；同一头条在两板通过不能凑数。当前冻结登记保持 8 项，历史 Git 源引用复核 30 项通过。
