## Shared record interface and bounded coverage

`interface.json` defines a values-only record and hidden `r29_observe(snapshot)` interface. All addresses are opaque to the logger. Copy values while existing code owns them; do not add unwrap/GetState/ref/provider calls, raw tail reads, extra JNI exception queries, or unsynchronized state reads. Missing values carry valid bits, never fabricated zeros. Snapshot under existing locks when required, emit outside them; no object pointer is later dereferenced by the logger. Keep original publication and release ordering.

Each DSO reserves16 diagnostic identities ×8 transition epochs ×6 phases ×(2 normal+2 error records), plus32 records partitioned into30 invalid/overflow, one FIRST_LIMIT and one FINAL_EXHAUSTION reserved for the first hard identity/epoch/total exhaustion. Invalid traffic cannot consume either reserved marker. At768bytes each this is at most3,104 records/2,383,872 bytes per DSO. Fixed-size storage; one regular-sink write per record, no retry, truncation marked, atomic saturation/no wrapping under concurrency. Exhausted hot paths check cheap eligibility before formatting/time/write. CPU key uses wrapper/trusted OH; consumer key uses trusted native state or producer old/new endpoint. A new wrapper/transition has its own allowance, so10,000 initial frame calls cannot consume it. Repeated same configuration, failure or frame token must not create epochs. Exceeding identity/epoch bounds emits explicit coverage exhaustion; it must not reject application work. Same-key transitions not visible at these hooks remain unknown rather than silently promised coverage.

CPU phases: cache-begin, lock-entry, prepare-output, lock-return, flush-return, geometry-return. Invalid gate input logs only opaque wrapper/caller and unknown OH. Reports preserve raw provider rc as well as normalized public rc. Consumer phases: attach, detach, update, producer-replace, producer-destroy, invalid. A record may encode entry and result together where the original call returns; failure/early-return records identify that no provider call ran. Use per-call sequence/TID/time and native OH for correlation, not JNI local-handle equality or matching counters from separate DSOs.

Before enabling logging, duplicate fd2 into a private CLOEXEC descriptor and verify a regular-file sink (S_IFREG/dev/inode). Hold that same open-file-description, never rebind/expose the diagnostic fd, and check it before eligible writes. Replacing the original fd2 does not redirect this held sink. A pipe/socket or failed/drifting identity disables observation with coverage UNKNOWN; do not fall back or change signal dispositions. Real closed-reader pipe tests must prove zero writes and no SIGPIPE; fake EPIPE alone is insufficient. External receipts must expose disabled coverage since a failed sink cannot promise its own warning. This is diagnostic fd ownership only, not new window/image references.

Producer ref/unref have separate called/rc_valid/rc fields, including unequal results. The common raw_rc field cannot overwrite either. Preserve void/ignored-return semantics and original control flow.

Every hook saves/restores errno at its insertion point. Immediately preserve post-provider errno before logging; restore it before subsequent original work. Do not change return/exception/ref/fence/format/cleanup behavior. Logging failure is a separate diagnostic loss, never a provider failure. A failed/hung original call need not produce a return record; do not invent completion from entry alone.
