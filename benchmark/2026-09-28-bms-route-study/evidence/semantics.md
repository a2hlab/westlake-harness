# PMS/BMS source corrections (appendix only)

Status: source inspection verified; no build, host test, or device execution. Paths below are relative to read-only `00.Workspace`. This appendix preserves findings gathered before the task changed to execution preparation.

- The current `resolveService` and `queryIntentServices` call `queryCanonicalComponents`, which calls the standalone `ComponentStateResolver`, not the old `nativeQueryAbilityInfos` BMS entry. The wrapper loads a root-controlled library from `/data/local/tmp/oh-adapter-component-state`; JNI starts the canonical resolver. Its backend reads package-store, component-index and caller-scope files and consults component state. A copied Java class alone is therefore insufficient. Sources: `src/adapter/framework/package-manager/java/PackageManagerAdapter.java:795-842`, `src/adapter/framework/package-manager/java/PackageManagerAdapter.java:1174-1186`, `src/adapter/framework/package-manager/compatibility/java/adapter/compatibility/ComponentStateResolver.java:3-30`, `src/adapter/framework/package-manager/jni/component_resolver_jni.cpp:46-111`, `src/adapter/framework/package-manager/component_resolver/src/component_resolver_runtime_v1.cpp:22-49`, `src/adapter/framework/package-manager/component_resolver/src/component_resolver_runtime_v1.cpp:418-455`.
- `getNameForUid`, `getInstallerPackageName` and `getInstallSourceInfo` still log a stub and return null. Sources: `src/adapter/framework/package-manager/java/PackageManagerAdapter.java:1102-1106`, `src/adapter/framework/package-manager/java/PackageManagerAdapter.java:1413-1423`.
- The old parser retains action/category and scheme/host/literal-path/MIME; it attaches filters to activities, services and receivers. Its exported fallback promotes false to true whenever a filter exists, without distinguishing an explicit false in this branch. It lacks port/path-prefix/pattern fields in this model. Sources: `src/adapter/framework/package-manager/jni/apk_manifest_parser.h:28-38`, `src/adapter/framework/package-manager/jni/apk_manifest_parser.cpp:611-642`, `src/adapter/framework/package-manager/jni/apk_manifest_parser.cpp:670-696`.
- The old `ApkBundleParser` maps MAIN/VIEW/SEND/PICK to `ohos.want.action.home/viewData/sendData/select`; other actions gain the OH prefix. DEFAULT/LAUNCHER/BROWSABLE map to default/home/browsable entities, INFO also maps to default. Only the activity loop copies skills; service/receiver/provider branches construct empty inner-extension records, and the local module is explicitly discarded. Treat this as incomplete mapping code, not proof that installed BMS skills are complete. Sources: `src/adapter/framework/package-manager/jni/apk_bundle_parser.cpp:50-66`, `src/adapter/framework/package-manager/jni/apk_bundle_parser.cpp:126-217`.
- The canonical matcher implements action equality, request-category inclusion, default-only filtering, MIME wildcards, scheme/host/port/path-prefix matching, explicit component lookup and visibility/export/permission/enabled filters. It supports user 0 and only three flags (`MATCH_DISABLED_COMPONENTS`, `MATCH_DEFAULT_ONLY`, `MATCH_SYSTEM_ONLY`), fails on declared unsupported patterns, and sorts candidates explicitly before `resolveService` takes the first. This is reusable matcher code with integration and semantic limits, not a complete Android equivalence claim. Sources: `src/adapter/framework/package-manager/component_resolver/src/component_resolver_v1.cpp:21-32`, `src/adapter/framework/package-manager/component_resolver/src/component_resolver_v1.cpp:81-205`, `src/adapter/framework/package-manager/component_resolver/src/component_resolver_v1.cpp:489-529`, `src/adapter/framework/package-manager/component_resolver/src/component_resolver_v1.cpp:614-688`, `src/adapter/framework/package-manager/component_resolver/src/component_resolver_v1.cpp:728-740`.
- The newer `manifest_facts` component parser records kind/name/optional exported, not a ready intent-filter catalog. `bms_projection` supplies a transactional adapter interface and digest/identity payload, not a concrete HAP skills generator. Sources: `src/adapter/framework/package-manager/manifest_facts/src/manifest_facts_v1.cpp:837-884`, `src/adapter/framework/package-manager/bms_projection/include/bms_projection_v1.h:122-145`, `src/adapter/framework/package-manager/bms_projection/include/bms_projection_v1.h:192-214`.

Its queryAbility/queryExtensionAbility declarations require system APIs and `GET_BUNDLE_INFO_PRIVILEGED or GET_BUNDLE_INFO`; they are not evidence of stock OH 6.1 permission behavior or end-to-end service projection. An OH 6.1 projection HAP remains an unexecuted hypothesis.
