# Westlake 本地能力证据：用于 D2R Mobile 对照

审计日期：2026-10-16；本仓固定提交：`3aafa744df6b66fbda8651b6925e63cbd5186daa`。仅阅读本仓代码与已落库真实结果，未访问设备、未重做部署或游戏验证。本笔记不独立审计 D2R 源码；对方部分由主研究负责，对照固定提交为 `211be64fcfbc6d73a4ec08fd238b42f1caa2181f`。因此以下结论是“我们已有可验证的工程能力”，不是“对方没有”或总体技术领先。

**可直接回答用户：最有证据的差异是，把一次适配变成能跨 APK 复用、受冻结约束、有部署身份和回滚证据、能追到实际源码/构建入口的兼容平台。现有材料不能证明我们在单游戏可玩性、性能、长时间稳定性或移植效率上优于 D2R Mobile。** D2R 自己已有回归验证，不能拿“我们有测试”作为独占优势；同样，单游戏目标不能被偷换成没有可复用架构。

## 1. 跨 APK 公共 API 的积累：制度、工具、历史实测都有

- **制度**：冻结要求至少两个不同 app 越过同一个公共 API 障碍，其中至少一个 t20 实际上屏；“另一个 app 过墙”不等于该 app 完全可用。见 [knowledge/frozen/FROZEN.md:L3](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/knowledge/frozen/FROZEN.md#L3)。当前只有 **8 项冻结条目**，不是 315 项冻结 API。
- **源码与执行门**：`check_frozen.py` 校验登记规则和逐源码/产物身份；`deploy_generation.py` 明确调用仓内 checker，拒绝部署冻结身份漂移，也约束回滚目标。见 [scripts/lab/check_frozen.py:L54](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/check_frozen.py#L54)、[scripts/lab/check_frozen.py:L151](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/check_frozen.py#L151)、[scripts/lab/deploy_generation.py:L81](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/deploy_generation.py#L81)。本次本地只读实跑 `python3 scripts/lab/check_frozen.py --git`，rc=0，原输出汇总为 `frozen: 8 entries, 30 checked, 0 violation(s)`。这是历史 Git 对象校验，**不是**当前板上 8 项行为全通过。
- **实际例子**：FZ-002 让 Android ActivityThread 在显式大栈 pthread 上运行，生产源码确有 `pthread_attr_setstacksize` / `pthread_create` 和 `[CM-BIGSTACK]` 标记：[sources/api-implementations/FZ-002/src/child_main_after_stock.cpp:L352](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/sources/api-implementations/FZ-002/src/child_main_after_stock.cpp#L352)。冻结记录列出 Tusky、AntennaPod、Markor、K-9、Auxio 上屏及日志；同一代 5cd 实际 sweep 报 66 keys、126/126 截图、21 个 t20 视觉亮屏，名单包含上述五项：[knowledge/frozen/FROZEN.md:L45](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/knowledge/frozen/FROZEN.md#L45)、[benchmark/2026-09-30-unified-r17r-5cd-sweep/results.json:L9](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-09-30-unified-r17r-5cd-sweep/results.json#L9)。
- **另一种明确限度**：FZ-003 asset fd 是 NewPipe 亮屏、uhabits 只越过 `nativeOpenAssetFd` 障碍，后者随后仍撞 hwui；FZ-008 `SSLSockets` 本身包含 false/no-op 行为。不能将登记条目包装为完整 Android API 实现。见 [knowledge/frozen/FROZEN.md:L46](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/knowledge/frozen/FROZEN.md#L46)、[knowledge/frozen/FROZEN.md:L51](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/knowledge/frozen/FROZEN.md#L51)。
- **对照价值**：能证明修一个公共层问题让多个独立 APK 受益，并把已取得行为作为后续部署约束。不能由本仓记录推断 D2R 不做 ABI/HLE 复用；只能在对方已审范围没有相同证据时说“尚未看到同等跨 APK 冻结验证”。

## 2. 部署前 static/namespace 分析：有真实二进制已知答案，不只是约定

- **代码**：`open_site_scan.py` 枚举逐 PC 的 dlopen/dlopen_ns、路径、flags 与 namespace；明确保留 `UNRESOLVED`、可能多 namespace 和控制流不确定性：[scripts/lab/open_site_scan.py:L2](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/open_site_scan.py#L2)。部署静态门另外绑定包文件、checker、例外表与受限实验身份，防止“审过的对象”和执行时对象不同：[scripts/lab/deployment_native_gate.py:L65](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/deployment_native_gate.py#L65)、[scripts/lab/deploy_generation.py:L561](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/deploy_generation.py#L561)。**不要把 standalone open-site scanner 说成每条部署路线都自动强制运行。**
- **实际结果**：对四个哈希固定的真实 host 二进制重放。U9 为 6 open sites / 14 namespace edges；实际激活过的 U10 r2 为 8 sites / 18 edges，检出 1 个重复继承；accepted r3 为 8 / 17、无重复继承。记录还保留 r3 上其它 may-path findings，没有人为抹掉以制造全绿。见 [benchmark/2026-10-02-namespace-edge-scan/README.md:L17](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-10-02-namespace-edge-scan/README.md#L17)、[benchmark/2026-10-02-namespace-edge-scan/README.md:L31](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-10-02-namespace-edge-scan/README.md#L31)、[benchmark/2026-10-02-namespace-edge-scan/README.md:L52](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-10-02-namespace-edge-scan/README.md#L52)；原机器结果含输入 SHA、argv、rc=0：[benchmark/2026-10-02-namespace-edge-scan/results.json:L8](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-10-02-namespace-edge-scan/results.json#L8)。
- **局限**：这是离线二进制分析与已知答案验证，不是新的设备因果实验；静态 may-path 不证明实际走过路径，更不证明没有内存破坏或时序问题。合理改进方向是减少重复 namespace/加载错误造成的板上试错，不是宣称静态扫描能保证兼容。

## 3. 真实部署身份、失败关闭与回滚：有可执行实现，也有失败实证

- **代码**：部署器检查关键运行库 maps 数量/路径，并拒绝跨 boot 回滚：[scripts/lab/deploy_generation.py:L110](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/deploy_generation.py#L110)。`board_run.py` 在 finally 内执行 `before_unlock`，恢复失败则保锁：[scripts/lab/board_run.py:L330](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/scripts/lab/board_run.py#L330)。具体 BACK51 实验器还按 boot、PID birth、当前 SHA 和元数据守卫操作：[benchmark/2026-10-14-toutiao-manual-repair/back-callback-overlay/window_remote.sh:L23](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-10-14-toutiao-manual-repair/back-callback-overlay/window_remote.sh#L23)。
- **真实身份规模**：61b 最终 collector/consumer/compiler/verify 原链路 rc 均 0，独立捕获 **824 files + 130 package identities** 后 live954 PASS；这里的 954 是身份断言数，绝不是 954 个成功应用或 API 测试。见 [benchmark/2026-10-09-demo-boatattack/v2-20261013/outer/final61b-finalization/completion.json:L2](https://github.com/a2hlab/westlake-harness/blob/3aafa744df6b66fbda8651b6925e63cbd5186daa/benchmark/2026-10-09-demo-boatattack/v2-20261013/outer/final61b-finalization/completion.json#L2)。该 completion 自身 `V2_signed=false`，不能拿它替代后续签认，也不能推成当前设备状态。

## 对“新项目带来哪些改进”的可核实说法

上述是**已有基线**，不能算作新项目已经带来的收益。新项目若声称改进，应与同一个 baseline 对比：它新增了哪项公共能力、让哪些原有首个致命点消失；是否让至少两个不同 APK 获益；是否保留已有冻结行为和同设备回归；是否补齐过去缺失的源码/构建回执；若主张速度或性能提升，另有同硬件同场景的耗时/FPS/帧时间和重复次数。当前本地证据足以展示通用化、回归可审计与部署追溯的工程积累，**不足以排名谁“更先进”**。

审计边界：本笔记只新增本文件。未把制度当完成证据，未把 scanner 无告警当运行正确，未把源码引用数当 API 实现数，未将历史封板记录解释为今天设备稳定。历史报告的 raw 路径/哈希属于出处，未在此次审计中重拉所有大型私有制品。
