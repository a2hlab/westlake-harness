R16's first card treated the reachable `6c2dcfa6` lock stub's "not implemented" message as evidence that its behavior differs from deployed shim `85c789f4`. **That inference is incorrect.** Source lines 1257–1274 log once, set `errno=ENODEV`, and return `-ENODEV`; unlock sets the same errno and return. These are compatible examined behaviors. They **do not prove** a complete matching source snapshot, historical producing toolchain, whole-ELF identity or reproducible build.

The source excerpt is a numbered projection of the original `6c2dcfa611ba04f443e9a025f7c6eab5108db1192de37f33508a82a081619494` file. `exact-shim-instructions.txt` copies the already-reviewed instruction excerpt; its upstream private-source index is pinned, so it is not represented as a new disassembler run. A new independent app-private diagnostic DSO is **not ruled out** by missing whole-library reproduction. It could record pointer scalars and transparently call an explicitly established original target, preserving arguments, return and errno without reading unknown objects. However, current evidence does not establish natural player binding: `candidate-r9/run.sh:33` sets host `LD_PRELOAD`, while `:36–37` set Android namespace inheritance and a **single-path** `WESTLAKE_ANDROID_NATIVE_PRELOAD`. Appending a DSO or using an inheritance name does not prove precedence over player dependencies, caller isolation, or unique original provider selection. Exact deployed loader/open-site/scope evidence is a separate gate. No GOT or binary patch is proposed here.

The already measured player slots are `+0x472688` → android765 ELF `0x3b9c` and `+0x472490` → shim85 ELF `0x5e48`. A wrapper calling that android entry records its **outer forward target**. The bridge is the lookup handle/dependency scope, not the location of that helper. The actual inner winner remains unknown; a separate lookup cannot silently substitute for it.
