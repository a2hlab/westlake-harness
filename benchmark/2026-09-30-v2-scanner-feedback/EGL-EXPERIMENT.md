# Runtime-only: repeated-window EGL surface creation

A DEX call to `eglCreateWindowSurface`, an Activity transition, or a blank screenshot cannot establish that the same live OH NativeWindow already owns a surface. B10 therefore emits **runtime-only for every scanned key** and assigns no static-hit credit. In particular, an APK without direct EGL calls can reach HWUI through framework View rendering.

The v2 evidence is limited to target-PID `EGL_NO_SURFACE`/abort records. The later outer-loop experiment is separate, under `westlake-harness/benchmark/2026-09-30-egl-5ea/runs/egl-apps/`; its copied, hashed line excerpts are in `evidence/later-egl-experiment.json`. Wikipedia lines 61300–61304 / 65620–65624 and Noice lines 39668–39672 / 39701–39705 report `0x3003` both before and after removing colorspace attributes. This rejects colorspace removal as a sufficient repair in that experiment; it does not independently prove which owner failed to release its live surface.

## Discriminating experiment for the board-owning lane

1. Pin APK, package, boot, installer, JAR and native-library hashes. Use Wikipedia/Noice as cases and HelloWorld/ZigZag as controls. Record the exact launched Activity and app PID; an installer-selected entry and a secondary launch are distinct treatments.
2. Record, on one monotonic timeline: IWindow/session token and generation; `relayout` input/output size and flags; `resized` reason/count; ANW shim and unwrapped OH NativeWindow identity plus allocation generation; EGLDisplay/config; create/destroy return values and immediate `eglGetError`; surface bind/unbind and owner/lifetime. Pointer equality without lifetime generation is insufficient because addresses can be reused.
3. Run a baseline and one intervention at a time: (A) allow one reverse-push per actual window lifetime while preserving required first layout; (B) native ownership/lifetime correction reviewed by the native lane. Keep fresh-process/data conditions equal. Do not combine Java and native repairs before attributing the effect. The frozen r17j Java decision is at `../2026-09-30-v3c-r17j-prospective/freezes/v2/evidence/WindowSessionProxy.java:94`, and the reverse-push implementation starts at line 210; native and Java dispatch counts must be observed separately.
4. **Repeated-live-surface supported:** same lifetime generation has one successful create, no successful destroy/release, then another create returns BAD_ALLOC. **Repeat-dispatch trigger supported:** intervention A removes that second create and allows a captured own-content frame, while controls remain visible. **Lifetime repair supported:** B restores a valid create/bind/submit sequence without destroying a surface still referenced by another owner. **Alternative resource failure:** first create on a new lifetime already fails or failure persists after release/once-only dispatch; investigate allocation/config/native-window validity instead.
5. A successful EGL surface is not a first-frame pass. Check buffer submission/presentation and `snapshot_display` content. AppManager's surface-created-but-blank outcome is a separate first-frame/lifecycle case and must not be labeled BAD_ALLOC without its own error record. Record screenshot and process counts from `record.json`/process tables; missing evidence is unknown.

No experiment was run by this offline scanner task. Later experiment excerpts are explanatory evidence only, excluded from v2 calibration denominators.
