0. **Outer arms.** Re-run the same generator with `--enable --approved-by 'outer(codex)'` and the same

3. **Apply.** `deploy.py --plan --execute` stages the previously absent ROOT, verifies every file, then
   does the cfg CAS `7b9f2c0e` → after, expecting `PLACED_REQUIRES_NEW_BOOT`. The r3 ROOT, its stale

4. **Old-epoch exit by normal reboot** (G01 method). The old r3 guardian 4016, parent 5089 and the
   socket end with boot `be4badc3`. There is no signal and no takeover. `entry.sh` refuses an existing
   socket, so the new guardian must start its own parent. **The plan does not assume r3 recorded an
   r4c epoch:** r4c main writes `parent-epoch phase=bound` after its own `start-parent`.
   - Read back `parent-epoch`. `phase=unbound` (or missing) means a host-recreation switch is
     impossible; record it as the first refusal.
   - 61b reboots can drop off the hub (RUNBOOK l.11); tell the user before rebooting.
5. **Acceptance**, two cycles per T37:
   - normal close → desktop icon → feed → ordinary video card → 20 s of changing content frames →
     pause 3 s / resume 10 s → exit and re-enter;
   - screenshots + facts;
   - injected taps vs user observation recorded separately;
   - a host-recreation reentry counts only if `newhost` / `parent_epoch_switched` events actually
     appear.
6. **Retain or roll back.**
   - Retain only with an actual outer signature.
   - Otherwise `deploy.py --rollback --boot CURRENT --apply-receipt ACTUAL`: cfg CAS back to `7b9f2c0e`,
     reboot, read back the r3 chain, actual loaded SHAs, screenshot and power/debug, then UNLOCK.
   - Budget (G01 numbers): stop experiments at 1000 s, decide restore by 1200 s, unlock by 1800 s.
   - A transport-unknown result triggers read-only reconciliation only.
