# Toutiao device provisioning pipeline (#48 device-horizontal) — 2026-09-27

Reproducible, scalable pipeline to light up the Toutiao delivery (feed on the physical screen + selfheal
watchdog) on any OH 6.1.0.31 DAYU600 board. Validated: one command provisioned **5cd1e3dd** to feed-on-screen
+ self-heal. **61b06572 (user demo) is hard-skipped and never touched.**

## Deliverables
- **`provision_toutiao.sh <SERIAL> [--with-aot]`** — idempotent, board-adaptive one-board provisioner.
- **bundle/** (in scratchpad, gitignored for size; MANIFEST.sha256 committed) — the deployable Toutiao delivery:
  - `tt-rt.tar` (755 MB) — RT core: libart 78e34445, boot image (oat 247), fw BCP jars, webview-t-lib
    (libwebviewchromium + shim 85c789f4 with the #46 WebView fixes), app libs (metasec hollow/npth/etc.),
    runtime .so's, run.sh #50 (webview shim preload + file-JIT), prepare_jit50.sh, apks. EXCLUDES per-device
    profile (app-data/data/webview-t-data — regenerated by the watchdog) and the AOT oat (Tier-2, see --with-aot).
  - `tt-stage.tar` — source_app_namespace, host_spawn, request.bin.
  - `tt-wd.tar` — selfheal watchdog.sh + start-parent.sh (dynamic WL_PARENT_ID) + spawn.sh + screen-gate
    + **onscreen_keeper.sh** (keyguard-dismiss daemon, see On-screen adaptation below).
  - `aot/toutiao.{art,odex,vdex}` (762 MB, from VM out-speed-delivery50 = c7ad2a0b/e6f5c1aa/5ed9e8b2) — the #50
    AOT speed layer, deployed only with `--with-aot`. Feed renders WITHOUT it (ART falls back to JIT).
  - `source-host.hap` (df385638) — name/icon host (红头条 / 今日头条).

## Batch / scale to N boards
```
for SN in $(hdc list targets); do ./provision_toutiao.sh "$SN"; done   # 61b06572 auto-skipped
```
Each board: connect → run → feed on screen. Idempotent (safe to re-run; cleans + re-extracts each time).

## Board-adaptation (how one bundle fits any board)
1. **Host**: `bm install` the bundled source-host.hap every run (replaces whatever host is there).
2. **WL_PARENT_ID**: the bundled start-parent.sh resolves the live `imehost0` window id via hidumper at EACH
   launch and seds it into run.sh — so the app sub-window attaches to THIS board's host window, and survives
   self-heal / host restarts (this was the on-screen fix from benchmark/2026-09-27-toutiao-onscreen-fix).
3. **Self-contained RT**: brings its own libart/boot/fw/appspawn-x; only needs an OH 6.1.0.31 DAYU600 firmware
   base (musl linker /lib/ld-musl-aarch64.so.1, /system/lib64/platformsdk). A board missing that → the script
   reports FAIL with the child stderr.

## Board-difference bug found + fixed (make the bundle self-contained)
`source_app_namespace` (source_app_namespace.c) binds `$RT/private-tmp → /data/local/tmp` then
`$RT → /data/local/tmp/asx`, so **`$RT/private-tmp/asx` must exist as a mount point** (and private-tmp/app-data/
i18n/etc/icu must be owned by uid 20010053). The bundle excludes the runtime private-tmp (crash logs), so the
provision recreates `$RT/private-tmp/asx` (+ profile dirs) — without it source_app_namespace fails
`perror: No such file or directory` and the watchdog reports PARENT_BLOCKED. (Root-caused from the source.)

## On-screen adaptation: OH keyguard vs a "black" screen (generalized into the provisioner)
The single biggest board-difference for *staying* on screen is **OH's SceneBoard keyguard**
(`SCBScreenLock`). It auto-fronts on any screen-off→on transition and covers the (alive) `imehost0`
host window. The result *looks* like a black screen or a crash, but nothing crashed — diagnose it by
**window ZOrder**, not by process liveness or the gate:

| State | SCBScreenLock ZOrd | imehost0 ZOrd | On screen |
|-------|--------------------|---------------|-----------|
| keyguard covering (apparent "black") | **2000** (fronted) | **-1** (hidden) | ❌ lock |
| dismissed (feed visible) | **-1** | **101** (fronted) | ✅ feed |

The fix, folded into `provision_toutiao.sh` (step 7 launches it; cleaned up in step 1):
`onscreen_keeper.sh` — a resident daemon (same nohup/heartbeat/stop-file pattern as the watchdog) that
every 5 s (a) re-asserts `power-shell timeout -o 86400000` + full brightness so the screen never idles
off (idle-off is what re-arms the keyguard), and (b) if `SCBScreenLock` is fronted (ZOrd ≥ 0),
`power-shell wakeup` + swipe-up (`uinput -T -m 600 1700 600 200 300` ×2) to dismiss it and re-front the
host. It's **event-driven** (only swipes when the lock is actually covering) so it doesn't fight a real
user. Validated on 5cd1e3dd: natural 70 s idle → no re-lock; forced `power-shell suspend` → keeper
recovered the feed in **~4 s** (log: `keyguard fronted (ZOrd=2000) → after-dismiss lock=-1 host=101`).

Two board-shell gotchas baked into the keeper: the OH DAYU600 rootfs shell has **no `awk`/`tr`**, so it
splits the hidumper columns with the `set -- $line` builtin (`$8` = ZOrd); and `screen-gate`
**false-negatives (`unknown`) on video-heavy feed scroll positions**, so the provisioner's pass/fail
now keys on **ZOrder + watchdog `READY`** (host fronted, keyguard dismissed) and treats `gate=feed` as a
secondary confirmation only — otherwise a board actually showing the feed could be wrongly failed.

| Device | Toutiao feed on screen | Self-heal | Notes |

**Devices lit: 3 / 3** (61b06572 demo + 5cd1e3dd + 5ea34a45). Pipeline scales: any further board
that connects is `provision_toutiao.sh <SN>` away from Toutiao-on-screen — **and now stays on screen** across
idle/re-lock because the on-screen keeper ships in the bundle and is started by the provisioner. The 5ea34a45
run proved the provisioner drops cleanly onto a board that just finished the app-breadth sweep: pre-clean
(kill all `appspawn-x` = the sweep's per-app source spawns + `rm` the staging/source-RT dirs), then provision.
