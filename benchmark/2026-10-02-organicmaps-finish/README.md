# Bounded OrganicMaps rollback cleanup

The 61b U10.1 supplementary finish refused rollback because OrganicMaps children were still live. The old executor stopped there and needed a manual intervention. Rollback now catches only the exact existing live-child guard, resolves `app.organicmaps` through BMS, verifies its nonroot app UID and unique root appspawn-x parent, and calls the existing cold_stop primitive. That primitive rechecks PID/PPID/UID immediately before each signal. The original stop guard is re-entered after each attempt; it remains authoritative.

Two cleanup attempts at most (three stop calls). Activation admission remains unchanged. Every attempt writes a fresh receipt with before/after process rows and the cold_stop result. Unknown UID, foreign parent/app, transport failure or continued respawning still fail closed and retain the window lock. No automatic uninstall, parent signal, foundation restart, board reboot, native change or identity relaxation. This fixes automatic recovery of quiesceable residuals; it does not claim to eliminate OrganicMaps' unproven respawning cause. Keep OrganicMaps out of shared 61b observation shards until its isolated cleanup investigation succeeds (the new N11g plan does not include it).

Eight focused offline tests cover normal recovery, clean path, bounded persistent respawn, wrong ownership, unrelated errors, failed transport receipt, retained layers on failure and exact baseline restoration on success. Existing executor tests also pass. No device I/O was performed by this change. The source is the existing bms_batch cold_stop and deployment stop guard, not a replacement process-killing implementation.
