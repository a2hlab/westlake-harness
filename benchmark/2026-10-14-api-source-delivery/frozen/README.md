The default tree was not an accurate source location for every frozen API: FZ003 had an old same-name AssetManager implementation, FZ004/FZ006/FZ008 frozen source paths were absent, and FZ002's registered benchmark filenames pointed away from the actual candidate. This delivery puts the exact implementation files in `sources/api-implementations/FZ-001` through FZ-006 and FZ-008. FZ-007 belongs to another lane.

All **28 frozen Git blob pins** match both stored objects and their recorded commit:path. FZ001 additionally uses a SHA-verified original source archive whose two contained production SO hashes equal frozen.json; binaries were checked but not extracted. Its final BMS source is SHA9acb4385, not the earlier c96e992d input. FZ002 uses source commit d8d7a3e0 identified by the original freeze audit. FZ004 and FZ006 also match their original build receipts' source SHA values. Each of the seven directories has implementation code, `provenance.json`, an executable build entry, BUILD.md and preserved license information. Original recipes containing author machine paths are retained as non-executable evidence; new entries use explicit environment/CLI paths. The existing user-path gate passes. All seven build entries pass help and shell/Python syntax checks. **FZ004 and FZ008 were actually compiled using javac8**, with classes kept outside the landing set. The first Bash3 empty-array failure is retained; the corrected wrapper passes without changing original Java bytes.

Source-unit availability and full native build closure are separate. Large AOSP/OH trees, original generation link inputs and multi-fix JAR inputs remain external; their available hashes and acquisition locations are recorded. Where a full source lock is unavailable, the gap remains explicit. FZ008 is the original false/no-op compatibility fallback, not a complete TLS feature implementation. No native rebuild, device test or complete 315-row closure is claimed by this slice.
