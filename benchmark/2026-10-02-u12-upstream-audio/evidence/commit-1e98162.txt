    OpenSL ES adapter: Android configuration interface, canonical IDs
    
    SL_IID_ANDROIDCONFIGURATION is Android-only and OH's libOpenSLES has no
    such symbol, so libraries that import it failed to relocate: Godot's
    (Ball2Box, Jigsaw, V3, Duck Run) and Oboe's (Rhythm Engine). It is now
    exported with AOSP's value, kept out of the interface lists OH sees, and
    answered by a per-object interface that takes and reports the keys AOSP's
    player and recorder accept (stream type, recording preset, performance
    mode), with AOSP's error codes for unknown keys and short buffers. OH has
    no equivalent, so the values are recorded, not applied; the Java-proxy
    calls are unsupported.
    
    OH compares interface IDs by address. A library loaded in the isolated
    Android namespace binds its SL_IID_* references to that namespace's copy
    of libOpenSLES, so OH refused Godot's own SL_IID_ENGINE and Godot ran
    without audio. Every ID handed to OH is now swapped for OH's own by its
    contents. Ball2Box's audio was checked by recording the board's output.
