## 6. why westlake's existing errno13 retry did NOT save metasec
link_stubs OpenNativeLibrary already retries 'failed to map library errno=13' via FindPackagedCopy:
  it accepts /data/data/<pkg>/app_lib/<name>.so and reuses a same-name file on the ClassLoader search
  path (/data/local/tmp/asx/lib/arm64-v8a) ONLY when SameImage = identical size AND identical sha256.
  For metasec: IDENTICAL-COPY log = 0, exception still thrown => SameImage failed => the app_lib copy
  is NOT byte-identical to the asx/APK copy. A hardening SDK rewrites its private copy, so the
  sha256 guard (correct in general) cannot reuse it. #41 separately verified the asx copy DOES load.

## 7. errno13 nature: EACCES on an executable mapping of an app-private data file
  path is /data/data/<pkg>/app_lib (normal_hap private dir), not /data/local/tmp/asx (permissive).
  Executable mapping there is refused by OH policy (SELinux normal_hap lacks execute app_data_file,
  or the dir is mounted noexec). This is a kernel policy, independent of libc (musl vs Bionic).

## 8. why intercepting the NPE (candidate B) is not viable
getBackgroundHandlerThread() returns a CACHED thread and does not rebuild a dead one.
Callers that guard the dead thread (so they are safe):
  classes5:  getBackgroundHandlerThread().getState(); if (state==RUNNABLE) use getLooper()
  classes20: getLooper(); if (looper != null) new Handler(looper)
X.DEv (classes21, the crash) does NEITHER: getLooper() -> new Handler(looper) with no null/state check.
westlake cannot add a check to app bytecode, and a dead app thread cannot be revived
(an UncaughtExceptionHandler runs AFTER run() has returned). So the only lever is to stop the
thread dying, i.e. make metasec's app_lib System.load not throw = candidate A.
