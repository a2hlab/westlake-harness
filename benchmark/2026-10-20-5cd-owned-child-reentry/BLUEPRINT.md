# T13: adopt once, exit, one real icon reentry

T12 reached feed from old START_FAILED once. It did not test a later child exit followed by a new manual icon. T13 is a short validation window, not a permanent deployment. This blueprint is implemented by the sibling derive/tool/ui modules; offline checks are recorded in results.json. Hardware review remains pending.

1. Reuse the pinned T12 executor for preview, persistent command receipts, board lock/window-start, exact hashes, awake preimage/override/restore and STOP cleanup. Give T13 a new attempt root. Preflight must require child **31210/birth7485570**, parent **19163/birth7265322**, boot **0525bb05-f714-42ad-90f0-ecdb10356c4f**, child UID20011300 and SceneBoard UID20010017. Repeat the exact guards on apply. A dead or replaced child rejects the window; no PID discovery can substitute another child. Require the old T12 guardian to have exited, with no competing guardian. Preserve its records and STOP.
2. Derive from the original R2 watchdog, not T12's deleted first-launch tail. Retain the actual `if TT_CHILD_PID` adoption branch (original lines506–512), with an explicit positive fixed-child requirement before the branch; make the missing-child else path a refusal. The existing branch calls child_owned and increments seq0→1, writes instance and enters actual monitor_child without spawning. Entry exports the exact receipt-bound TT_CHILD_PID/BIRTH. Unlike T12, entry admits exactly this owned child, not an empty owned-PID set. Keep the exact parent guard and no new-parent fallback.
3. Reuse T12's deadline/STOP guards and empty-owned-PID handling, but **replace seq>=1 completion with seq>=2**. Adoption is instance1; the only later successful spawn is instance2. Preserve sticky unknown hold after an entered failed spawn. No new generic state machine is needed. Add a bounded adopted-instance audit event so the outer can prove guardian/instance ownership before optional TERM; do not use a claimed feed as that signal.
4. Exit mode is fixed before execution. Natural mode emits no signal. For controlled TERM, verify receipt, lock, deadline, boot, parent and actual child_owned immediately before calling existing `rb_signal 31210 7485570 TERM` once. rb_signal repeats birth/UID/exe/run-inode checks; it must be preceded by the full child guard because rb_owned alone does not establish ppid/private namespace. Record dispatch intent before the command so timeout or lost receipt cannot trigger a retry. No parent/group signal, no KILL, no alternate PID. A successful kill return is not exit evidence. If the child exits naturally after adoption, observe it without sending TERM; if it was already absent at preflight/apply, refuse.
5. Existing monitor/exit-verdict must establish absent or same-birth zombie (Z), then AWAITING_REENTRY. Require a new verified desktop sample and a root-reviewed screenshot before the outer's single normal icon click. The exact original parent must still exist. Old hidden owned windows block until gone; do not clear them. Accept only a new owned PID/birth, real readiness and reviewed feed. Original child disappearance alone and host/alive/READY do not prove reentry.
6. Maximum600seconds includes the observation and normal cleanup, guardian deadline reserves60seconds. Reuse bounded post-deadline recovery only for same-receipt STOP/awake restore, not more UI/TERM/spawn. Stop only the new guardian; preserve parent, new child and app data. Read back original Override and unchanged Timeout. Failure retains lock and recovery_required. No cfg/runtime/JAR/APK replacement or reboot. Separate lifecycle mechanical results from human feed verdict.
