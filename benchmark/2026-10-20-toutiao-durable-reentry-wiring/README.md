**UI_UNVERIFIED does not mean the guardian exited.** R2 `main` writes AWAITING_REENTRY after the first monitor (lines521–526). On a later successful reentry, `monitor_child` returns0 for proven exit (390–405), `rc_after_spawn_ok` returns to the loop (460–468), and `reentry-common.sh` only resets `rc_arm=UNARMED` (140–151): it does not write another AWAITING state. Thus seq2's UI_UNVERIFIED can remain while the manual-wait loop runs. Fresh ps contains shell4016 and readlink27329 whose PPID is4016, consistent with active checking, but NAME alone cannot identify that shell as this guardian. No terminal OWNER_REFUSED/STOPPED event appears in the retained tail; absence of such an event is not proof of liveness.

One remaining read-only check is provided in `readonly-guardian-check.sh.txt`: bind current attempt `lock/owner` to matching live PID/birth, exact watchdog cmdline, status and STOP presence, with boot and owner/stat rechecks. A missing/mismatched owner or process is a specific failure to investigate, never permission to clear locks or launch another guardian. A matching live guardian supports reuse of normal desktop→icon handling, not guaranteed feed. The outer owns the actual command and any subsequent UI validation.
