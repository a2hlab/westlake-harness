## The patch worked partially
The npth no-inline-hooks patch (4f7cc3a6) gave warm 3/5 clean (read 3 real
articles) — npth's inline hooks were ONE real corruption source (0/5 -> 3/5). warm
is confirmed a MULTI-source SOURCE-NATIVE-LOAD monitor queue. Two residuals:

## r5 — NOT a patch regression; npth's sigaction struct overrun (non-hook path)
Thread npth-worker, SIGSEGV si_code=2 (SEGV_ACCERR), si_addr=0x7f76800000 (page
aligned), PC = musl `sigaction+0x1a4`, fault insn `str x8, [x19, #144]`.
- x19 = si_addr - 144 = 0x7f767fff70 — a REAL high address, NOT the fake stub. A
  "mov x0,#1" regression would fault near 0x91 (1+offset); this is a page-boundary
  write. So r5 is NOT introduced by the patch's fake-success stub.
- musl `sigaction` copies a 152-byte `struct sigaction` to x19 (its k_sigaction).
  musl's sigset_t is 128 bytes (1024 signals) vs Bionic's 8 bytes, so musl's struct
  is far larger. npth (Bionic ABI) passed a Bionic-sized sigaction buffer that sits
  144 bytes before a page boundary; musl's 152-byte write runs off the end into a
  read-only page -> SEGV_ACCERR.
- This is npth's NON-HOOK path — its signal-handler management — hitting a
  Bionic-vs-musl struct-size mismatch. It is exposed because the patch KEEPS npth
  loaded (the refuse would not, but the refuse is bypassed by SOURCE-NATIVE-LOAD).
- FIX direction (a further, deeper npth patch): neuter npth's sigaction handler
  install so npth-worker never calls musl sigaction with the Bionic struct. The
  westlake recorder (out-crash42) catches crashes independently, so npth does not
  need its own signal handlers. (Not built this turn — see task-2 first.)

## r3 — another SOURCE-NATIVE-LOAD lib's inline hook
Thread platform-single, mallocng 0xd6e20 (get_meta/free trap = metadata corruption
= the inline-hook signature). loaded_monitors: libjato, libgodzilla-memsponge,
libgodzilla-sysopt, libmonitorcollector-lib, npth (hooks neutered), engines. With
npth's hooks gone, the corruptor is one of the OTHER inline-hookers, which load via
SOURCE-NATIVE-LOAD (constructors) and so cannot be refused. Same mechanism as npth:
inline-hooking hot functions, shadowhook trampoline mismanagement on musl.
