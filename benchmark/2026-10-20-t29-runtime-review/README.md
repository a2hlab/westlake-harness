# T29 first fixed-prefix runtime review

A RequestBuffer failure before obtaining any buffer permanently poisons the same producer path in the deployed shim. The first observed raw error is `40601000` (normalized `-5`) at monotonic 253.905229 seconds, with null buffer, no handle/conversion/map/unmap/abort calls and `retained=1`. Within 0.606 ms the same wrapper/OH pair starts returning cache `-16` at stage 32. The initial provider rejection remains unexplained; persistent failure amplification is independently explained by the exact deployed source.

The production-pinned `window_module.c` failure path unconditionally calls `complete(..., success=0)`, marking the R14 slot failed and `retained=1`. `r26_finish` propagates that state to `R26_FAILED`; subsequent same-window `r26_lock_begin` calls reject it with `-EBUSY`. These source hashes match actual production inputs, not just same-named repository files. Any successor must distinguish a request that acquired no resources from uncertain retained ownership; this report proposes no deployed change.

The fixed prefix is 33,093,780 bytes, SHA `7254a067d87a3015bd999f4a86e74b91b24e9794fd985e7083df0ba762262d6a`. Transfer and selected-prefix recheck succeeded; global source immutability is not proven. Boot `68343d9d-8afb-4348-927c-c0f7d1c2b26b`, child 7635/birth 11561 and parent 5782/birth 10169 remain the reviewed identity. There are 42 R29 records: 27 CPU (including a cap marker), 9 producer-destroy and 6 producer-create. No consumer update/attach/detach records appear; this does not prove those JNI methods were invoked, or that consumer processing was healthy.

The trusted OH `7eef2e2790` is destroyed/recreated with successful unref/ref at monotonic 250.797/250.799 seconds. The request failure follows about 3.106 seconds later. Two saved uptime/date anchors place that failure approximately at 15:49:16–17 local time, shortly after the observed full-screen transition. The date values have second resolution and the reads are sequential, so this is approximate alignment. Existing EGL destroy records immediately precede the producer switch; another nonnull EGL image appears after the request failure. Neither fact proves continued pixel consumption.

Independent image inspection confirms changing video content before full screen: the temple view changes and a new subtitle appears between the 5- and 20-second captures. After full screen, all four original JPEG files are byte-identical for 19.96049 seconds. They show a central waterfall/Buddha/caption image with black margins, not an all-black image. Pause/content-static status and this window's audio remain unknown. These observations do not constitute a successful full-screen transition.

Actual five-slot reads all match: player lock/unlock/geometry bind to the new shim; bridge ref/unref bind to the same surface instance. Two surface mappings exist, so the paired result must not be restated as a single loaded copy. `five-slots.json` preserves the exact before/after identity and values. Initial RGBX2 geometry/output/flush and later YV12 geometry/output/flush both occur successfully before the transition; this supplies runtime coverage that was unknown in T28.

`events.txt` and `events.json` retain every R29 record with original line numbers. `results.json` includes source pins, anchors, exact failure sequence and bounded literal counts. Zero fatal-literal matches apply only to this selected prefix and do not imply absence of all runtime errors. `early-quick.json` remains the earlier unknown assessment. No device call or new REA call was made by this reviewer. Window cleanup/final outcome belongs to the outer report; this package is the first fixed-prefix analysis, not a seal signoff.
