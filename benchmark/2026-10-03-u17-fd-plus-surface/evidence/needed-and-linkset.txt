STATIC CHECK the dispatch asked for -- is OHCanvasRenderer in the same .so?  NO.
  * oh_canvas_renderer.o is NOT in link-argv.txt (the 112 objects); its header comment says its only consumer was the
    DEPRECATED android_view_surface_stubs.cpp.
  * OHCanvasRenderer (oh_canvas_renderer.h) uses the OH_Drawing_* NDK API (libnative_drawing.so) + OHGraphicBufferProducer.
  * The runtime's 23 NEEDED do NOT include libnative_drawing (nor any *drawing* lib):
      libEGL libGLESv2 libGLESv3 libskia_canvaskit.z.so libandroidfw libbase libutils libcutils libziparchive

  => Wiring S_nativeLockCanvas to OHCanvasRenderer would ADD oh_canvas_renderer.o (+ its OHGraphicBufferProducer TU)
     AND a NEW NEEDED libnative_drawing.so. That VIOLATES gate (3): "NEEDED same, only these 2 functions change".

GATE-COMPLIANT ALTERNATIVE (libs ALREADY NEEDED):
  The runtime already NEEDs libskia_canvaskit.z.so (skia) and libsurface.z.so. AOSP's own nativeLockCanvas
  (frameworks/base/core/jni/android_view_Surface.cpp) implements lockCanvas with skia: dequeue a buffer from the
  ANativeWindow, wrap its pixels in an SkBitmap, set the Java Canvas's native SkCanvas over it, return a non-zero
  locked handle; unlock = unlock+post the buffer. Doing the same in the shim uses ONLY already-NEEDED libs
  (libskia_canvaskit + libsurface) -> no new NEEDED, no new object -> gate (3) holds.
