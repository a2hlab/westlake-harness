# T23 minimal sequential observation wiring

T21's unfiltered full-buffer hilog capture timed out with boot output. Its launch helper captures an image before reading process identity. For short-lived children, collect identity and short logs immediately after the existing normal-icon click returns, before the slow screenshot/WMS/full module hash pass. Keep the six-file executor unchanged; no T23 artifact, boot, PID or candidate SHA is supplied here.

Use the existing outer holder/deadline/boot wrapper and BMS `Board.raw_shell`/`desktop_launch`, with one HDC operation at a time. The old `t21_launch.py` is a source reference, not a T23-ready command: its output directory/context are fixed. The only launch wiring change needed is to insert the quick read sequence after `desktop_launch` and before `capture`. Do not automatically re-click if the child exits. Retain the existing temporary-awake/restoration responsibility.

1. Read guardian current instance/state/recent events and full `ps -A -o PID,PPID,UID,NAME`. Match the current guardian child to the unique business process; use `/proc/PID/stat` birth, PPID, all four UID values, exe SHA, mount namespace and TracerPid=0. Parent UID is root, not the application's UID. No selection by truncated comm or stale event alone. Poll at most 30 seconds in this first quick observation, one second apart, bounded by the original recovery reserve; absence is NOT_REACHED, not a new retry authorization.
2. Capture `/proc/PID/maps` between exact identity guards in the same remote shell. Reuse the checks in `observe.guard(profile)` (lines 32–45) with fresh profile values. `collect_reader_profile.py` supplies the existing receipt/section design, but its fixed media/player/run pins and full-module pass must not be run unmodified against an unbuilt T23 candidate. No GOT read is proposed.
3. Resolve `/proc/PID/fd/2`, require the expected regular log file and its actual dev/inode, then collect a short `tail -c 65536` of that file with file identity and process identity before/after. Record pre/post sizes and actual bytes. This is a tail, not a whole-file prefix or guaranteed first-fatal capture. Do not run tail on an unvalidated pipe/socket. If the existing shell lacks this tail option, retain the rc and use the existing framed fixed-range reader only after fresh offsets/file identity are supplied; do not reuse its old PID/offset constants.
4. Run exactly `hilog -x -P PID -z 2000 -L D,I,W,E,F -v epoch` for that fresh child, host timeout at most 8 seconds and within the remaining window budget. The actual help supports all these individual options; their combined invocation is not claimed tested here. Capture raw stdout, stderr, transport rc, explicit remote hilog rc and pre/post identity results. Use a subshell to preserve hilog's rc before the postguard, then emit a unique completion marker; a successful HDC transport alone is insufficient. Do not append `head`, grep, a domain filter, or a time-range flag. Epoch changes format only. Local launch/action-time filtering is a derived view; keep raw output untouched, especially around PID reuse.
5. Then capture the screen. Repeat the same bounded serial reads around an authorized UI action if necessary; separate every new child/PID/birth group. No concurrent HDC collector/background stream. Preserve partial timeout output and mark missing postguard UNKNOWN, never silently complete.

Existing reusable code is pinned in `source-pins.json`. The T11 collector is also unsuitable as an unchanged CLI: its old boot/profile and 600-second contract are fixed. This card proposes a small outer-wrapper wiring change, not a new collector framework or executable admission. Neither maps, READY, a nonempty hilog, nor successful guard checks establish feed/video/audio success.
