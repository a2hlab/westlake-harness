# crash42 in-handler FP-walk — pin the non-hook mallocng corruptor (#48 path A)
date: 2026-09-27

## Why path a (chosen over path b)
Our v4b observer (a preload SIGSEGV handler) LOST the signal race: sigchain's `sigchain_trampoline`
(installed by ART, re-asserted every 2 ms via the re-assert thread, and hardened across fork by
pthread_atfork) OWNS SIGSEGV. Our early-preload sigaction handler is displaced and never runs at the
a_crash. Board re-verify: crash-o1 (0xd6e20) recorded by [CRASH42]; 0 [WGWP-OBS] blocks.

crash42 is the ONE handler that runs 100% at the a_crash (it produced all our evidence) and already
dumps pc/sp/fp/lr + all GP regs. It was missing only the free()/realloc caller chain. So instead of
racing it (path b: register another special handler via `AddSpecialSignalHandlerFn` — more moving
parts, ordering/claim semantics, struct-layout coupling), we add the FP walk to the handler that
already wins. It lives in a small standalone lib — lightweight to rebuild.

## The bug in the existing FP walk (why the board had no caller chain)
crash_snapshot.c already attempted an FP walk, but the whole stack section — raw stack dump AND the
FP walk — was inside `if (mem >= 0) { ... }` where `mem = open("/proc/self/mem")`, and each frame was
read via `pread(mem, ...)`. On the board `/proc/self/mem` is EACCES, so `mem < 0` and the entire walk
was skipped (only `mem_open_errno` was recorded). The stack VMA bounds `[lo,hi]` were, however,
derived from `/proc/self/maps` (readable) and available.

## The fix (crash_snapshot.c — the diff is the only functional change)
Add a mem-INDEPENDENT FP walk that runs whenever `[lo,hi]` is valid, using **direct in-process
dereference** of the stack (`*(volatile uint64_t*)fp`) — not `/proc/self/mem` — so EACCES cannot
block it. For each frame: read `[fp]`=next_fp, `[fp+8]`=saved LR; write `fp_frame_return`; resolve
each return + pc to lib+offset in-process via `dl_iterate_phdr` (walk each lib's PT_LOAD; addr−base =
file offset), emitting `fp_frame_lib=<name>`, `fp_frame_libbase=0x…`, `fp_frame_off=0x…`.
Guard against a bad fp faulting: fp ∈ [lo,hi], 16-aligned, `hi-fp >= 16`, saved_fp monotonic, ≤32
frames — a bad value stops the walk instead of dereferencing. Raw returns are written BEFORE
dl_iterate_phdr, so the chain survives even if resolution is unavailable.

## Safety
- Relaxes the recorder's original "no raw stack deref / no locks" posture, deliberately and bounded:
  the deref is gated by the actual [stack] VMA bounds (a value in [lo,hi] is mapped RW → won't fault);
  if [lo,hi] wasn't found (lo=hi=0) the walk is a no-op.
- dl_iterate_phdr takes the loader lock. The target a_crash is in mallocng (malloc/free integrity),
  NOT in ld.so, so that lock is free. Raw returns are written first, so evidence is preserved even in
  the pathological case. (If ever a concern for non-mallocng crashes, the raw returns + the per-event
  maps file already suffice for offline symbolization.)

   stack_bytes, maps, ucontext) still PASS.

## Deploy (claude-2 — overlay the deployed libsigchain.so)
Back up the on-device libsigchain.so first. Push the rebuilt libsigchain.so (sha 32c11986…) over the
deployed recorder's libsigchain.so, restart, warm-reproduce the ~11-17s 0xd6e20 crash. crash42's
event-*.txt now contains, for the detecting thread: fp_frame_return[] + fp_frame_lib/libbase/off per
frame = the free()/realloc caller chain resolved to lib+offset. Recv the event dir + hand to claude-3.

## What claude-3 does with it
The fp_frame chain names the ld-musl free/realloc path + the caller lib/offset that invoked into the
allocator on the detecting thread; cross-referenced with the registers (victim group/meta ptr) it
pins the writing subsystem → fix (patch / hollow / refuse / permanent musl malloc round-up).

## CORRECTION (2026-09-27): the deployable container is a RELINKED libart.so, NOT libsigchain.so
Outer loop (crash-census VM_READY.md L41): the standalone `recorder/libsigchain.so` is only an
independent link-check artifact and CANNOT be deployed. On the device the #42 sigchain is STATICALLY
LINKED INSIDE libart; the device candidate is a re-linked libart. My fp-walk patch in crash_snapshot.c
is correct — it just has to ride into libart, not libsigchain. The libsigchain.so build (sha 32c11986)
is VOID for deployment.

Mechanism = `out-crash42/fixture/scripts/relink_art.py`:
1. Reproduces the frozen #42 baseline libart byte-for-byte and asserts sha == 009a08fb…c8bbc (proves
   the relink env is faithful → the candidate differs from baseline ONLY by my change).
2. Verifies all 454 input object shas against artifacts.json.
3. Recompiles sigchain_musl_diag.cc → sigchain.o (replaces the baseline sigchain/sigchain.o) and
   APPENDS `out-crash42/recorder/crash_snapshot.o`.
So to carry the fp-walk: rebuild `crash_snapshot.o` from the PATCHED crash_snapshot.c (OHOS clang,
`-std=c11 -O2 -g -fPIC -Wall -Wextra -Werror -I fixture/native`), place it at
`out-crash42/recorder/crash_snapshot.o`, then run relink_art.py.
