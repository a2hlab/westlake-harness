ROOT CAUSE — the Android launcher icon is XML-only (adaptive icon), not rasterized at install:
  aapt2 dump badging com.frequent.habits_17.apk:
    application-icon-{160..640,65534}: 'res/BW.xml'
    application: label='Frequent Habits' icon='res/BW.xml'
    launchable-activity: name='com.example.MainActivity' label='Frequent Habits' icon=''
  aapt2 dump xmltree res/BW.xml:  E: adaptive-icon { background @0x7f05000e, foreground @0x7f05000f, monochrome @0x7f05000f }
  unzip -l: the only icon asset is res/BW.xml (548 bytes) — NO raster PNG in the APK.
  -> The installer records icon path .../android/icon.png (iconId 16777221) but the SOURCE is an <adaptive-icon>
     XML; the android->OH icon projection does not composite/rasterize the adaptive-icon layers, so there is no
     usable raster icon.png (the B3 DECLARED_XML_ONLY placeholder path lets the bundle INSTALL but leaves no
     renderable icon). SceneBoard has no icon to render for the entry ability -> it places NO desktop tile
     (hence the label text is absent from the launcher tree) -> the runner reports app_failed. The ability itself
     is installed and launchable, which is why `aa start com.frequent.habits/com.example.MainActivity` lights it.

CLUSTER: launcher-side icon projection (adaptive/vector Android icon not rasterized to an OH icon at install) —
related to DIGEST B3 (installer fail-closed/placeholder on pure vector icons).

MINIMAL FIX (installer icon projection — apk_bundle_parser / the android->OH icon extraction): when the Android
launcher icon is an <adaptive-icon> (or <vector>) XML, composite its background+foreground layer drawables
(vector-aware) into a raster icon.png (and populate the entry ability's iconId/iconPath so SceneBoard can render
it), instead of leaving the XML-only placeholder. Then SceneBoard places the tile.
