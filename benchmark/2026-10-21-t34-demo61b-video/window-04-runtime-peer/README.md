# W04 candidate runtime peer

Earlier candidate windows lacked direct evidence of the new parent's private runtime. W04 closes that specific gap: the guarded collector captured all six candidate files in physical, parent and child views. SHA-256, device/inode, size, mode and ownership match across all 18 observations and match the candidate profile. The transport rc and unique remote frame are both zero. Original parser replay reproduced the report object.

This evidence does **not** establish a usable app. Independent inspection of the first icon at t20, the subsequent observation at t70 and the single normal reopen at t90 found an empty gray content area, with no feed or video. The candidate fails this visual check; retaining it is not recommended. Restoration and unlock are outside this report and were still pending when these candidate facts were recorded.

The boot is `734294d3-4e1d-4b15-b71d-5d4dc9294d5f`. The collector's before/after process records agree for parent 5043/b5735, host 4840/b5549 and child 7110/b7383. The child is S at both collection endpoints. Bridge, shim and compat have exact-path map rows whose device/inode match the collected files. Media/player have no exact-path rows in this sample; their mapping status remains UNKNOWN. Maps do not prove linker-namespace identity or a dynamic symbol winner.

Later bounded receipts establish that child 7110 exited: both stat bodies report no such file, despite transport rc0; the parent tail reports signal 11 and child hilog records completion of signal handling. This does not attribute the exit to the candidate. Earlier library-loading warnings have no demonstrated fatal or causal role. No crash diagnosis was performed.
